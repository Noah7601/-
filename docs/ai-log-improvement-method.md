# AI 로그 기반 일일 개선 루프 (Kun Chen 방식)

## 1. 개념

| 단계 | 하는 일 | 실행 위치 | 주기 |
|---|---|---|---|
| ① 로그 계획 | AI가 "사용자 행동 / 내부 동작 / 눈에 보이는 결과"를 재생 가능하게 기록할 계획을 세우고 로그를 남김 | Claude Code 대화에 직접 입력 | 1회 (프로젝트당) |
| ② 일일 리뷰 | 지난 24시간 로그에서 고장·불편·낭비를 찾아 효과 큰 순으로 개선안 제시 | 예약 작업 | 매일 1회 |

## 2. 프롬프트 ① — 로그 계획 (대화에 그대로 붙여넣기)

```
이 프로젝트에 로그(기록) 계획을 세워줘.
목표: 나중에 AI가 로그만 보고 (1) 사용자가 겪은 일, (2) 내부 동작, (3) 눈에 보이는 결과를 그대로 재생할 수 있어야 해.

요구사항:
- 로그 위치: logs/YYYY-MM-DD.md (하루 1파일, 시간순 append)
- 각 항목 필수 필드: 시각 / 트리거(사용자 행동) / 내부 동작(호출·판단·소요시간) / 눈에 보이는 결과 / 상태(정상·고장·불편·낭비) / 비고
- 민감정보(토큰·개인정보)는 기록 금지, 마스킹 규칙 명시
- 어떤 지점에서 무엇을 남길지 목록으로 먼저 제시하고, 내가 승인하면 코드·훅·스크립트에 반영해
- 기록 누락 시 알 수 있도록 "로그 없음" 자체도 하루 1줄 남겨
```

## 3. 프롬프트 ② — 일일 개선 리뷰 (예약 작업에 입력)

```
logs/ 에서 지난 24시간 로그를 모두 읽어.
1) 고장(실패·에러), 2) 불편(사용자 재시도·우회·대기), 3) 낭비(중복 호출·불필요 토큰·긴 소요시간)를 찾아줘.
각 항목을 [영향도 × 빈도] 기준으로 효과 큰 순으로 정렬하고, 상위 5개에 대해
- 증상 / 원인 추정 / 개선안 / 예상 효과 / 작업량(S·M·L)
을 표로 정리해 reviews/YYYY-MM-DD.md 에 저장해.
추정은 "추정:"으로 표시하고, 로그가 없으면 "로그 없음"만 기록하고 끝내.
```

## 4. 예약 작업 선택

| 조건 | 선택 | 비고 |
|---|---|---|
| 내 Mac 파일(로컬 logs/)을 읽어야 함 | 데스크톱 예약 작업 (Claude Code 데스크톱 앱) | Mac이 켜져 있을 때만 실행 |
| Mac 꺼져도 돌아야 함 | 클라우드 예약 작업 (claude.ai/code) | 로그가 GitHub 레포에 push 되어 있어야 읽을 수 있음 |

권장: 로그를 이 레포 `logs/`에 커밋·push → 클라우드 예약 작업으로 매일 실행 → 결과 `reviews/`에 커밋.

## 5. 로그 템플릿 (logs/YYYY-MM-DD.md)

```
| 시각 | 트리거(사용자 행동) | 내부 동작 | 눈에 보이는 결과 | 상태 | 비고 |
|---|---|---|---|---|---|
| 09:12 | /deploy 실행 | build 42s → upload | "배포 완료" 출력 | 정상 | |
| 09:40 | 같은 질문 2회 입력 | 1회차 타임아웃 | 응답 없음 → 재시도 | 불편 | 추정: 네트워크 |
```

## 6. 체크리스트

- [ ] 프롬프트 ①을 대상 프로젝트 Claude Code 대화에 입력 → 로그 계획 승인
- [ ] 하루 돌려 logs/ 에 실제 기록 쌓이는지 확인
- [ ] 예약 작업 생성 (데스크톱 또는 클라우드) + 프롬프트 ② 입력
- [ ] 첫 reviews/ 결과 확인 후 개선안 1개 적용
- [ ] 1주 후: 리뷰 결과가 반복되면 프롬프트 ② 기준 조정
